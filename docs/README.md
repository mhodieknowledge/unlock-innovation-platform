## 2. THE PRODUCT IN ONE PARAGRAPH

African builders are not short of opportunities — they are flooded with them through Telegram and WhatsApp. They are short of **certainty**. For every listing they must personally work out whether it is still open, whether their country qualifies, whether their year of study qualifies, what is actually required, and who would do it with them — reading source documents on a phone over data costing up to $43.75/GB. This product does that work **once, structurally**, and gives everyone the answer: *this is open, you are eligible, here is the sentence that says so, here is the deadline, here is who else is going for it.* People and Projects are not a social network bolted onto a directory; they are liquidity generated by declared intent on a specific, dated opportunity.

---

## 3. THE SIX DECISIONS THAT SHAPE EVERYTHING

1. **Eligibility is deterministic.** AI extracts rules once at ingestion, with a verbatim source quote per rule. A pure function evaluates them per person. No LLM ever runs at query time. This is the product's spine and the only feature in the brief that is simultaneously valuable, unserved, free to run, and useful to the very first user with nobody else present.
2. **Freshness is the promise.** Every record shows when it was last checked. Automated re-verification, link health, change detection, community reporting. *"We never show you a dead opportunity"* is falsifiable, and it is what incumbents are worst at.
3. **Telegram is the primary push channel.** Free and unmetered, versus ~300 emails/day shared with authentication. This is what makes retention viable at $0, and it is where the audience already is.
4. **Density floors.** No social surface renders below a computed threshold. A room with four people is useful; a directory with four people is embarrassing. The product never shows an empty social surface to anyone.
5. **Bytes are money.** Enforced byte budgets per route, in CI. At Zimbabwe's data prices a 2 MB app costs a student about nine cents per load. This ruled out map tiles, third-party analytics, hero images and a heavy client framework.
6. **Colour is reserved for eligibility; typography carries urgency.** The interface is a status system, so the strongest visual channel is spent on the verdict and pure black is spent on one number — the countdown.

## 4. WHAT WAS REMOVED FROM THE ORIGINAL BRIEF, AND WHY

Full argument in `01_PASS2_CRITIQUE.md`. Summary, because a coding agent should not re-add these:

| Removed | Reason |
|---|---|
| AI judging simulator | Manufactures false authority; teams would optimise against a fiction produced by a rate-limited 8B model |
| AI hackathon copilot | Feature creep into a chat product we cannot win; commodity output |
| Generic AI idea generation | Any user gets better output free from ChatGPT or Claude in one prompt. Replaced by the **Brief Decoder** — extraction of what the rules already say, which cannot hallucinate |
| Global browsable builder directory | A social network with no liquidity; the documented graveyard pattern. Replaced by opportunity-scoped rooms |
| Open DMs | The largest moderation liability for a solo operator. Replaced by consent-bound requests and handoff to Telegram or WhatsApp |
| Open-source project discovery | GitHub labels, up-for-grabs, goodfirstissue.dev and CodeTriage own this. Ingest via the GitHub API instead |
| Achievements and gamification | Unverifiable at $0; self-asserted trophies corrode the trust the product is built on |
| Interactive Africa map | Decorative; map tiles breach the data budget; a country list answers the question faster |

Two features were substantially **reframed** rather than removed: natural-language search became a transparent query compiler producing editable filter chips (never an answering layer), and AI team matching became role-complementarity display only — we do not score humans against each other.

## 5. THE THIRTEEN INVARIANTS

Violating any of these is a defect, not a trade-off. They appear in the specifications with `[PR]` and are repeated in `IMPLEMENTATION_PLAN.md` §16.

1. Never publish an opportunity without a source URL.
2. Never store an eligibility rule without a verbatim source quote.
3. Never resolve eligibility ambiguity to `eligible` — ambiguity is `unclear`.
4. Never render a social surface below its density floor.
5. Never exceed a byte budget.
6. Never send user personal data to an LLM provider.
7. Never hard-code a model name.
8. Never call an LLM in a request handler, except the cached query compiler.
9. Never create fake users, teams, projects or counts.
10. Never let an AI failure produce a user-facing error — degrade and say so plainly.
11. Never commit a secret; the batch repository is public.
12. Never add a third-party script to a public page.
13. Never publish an opportunity that charges a fee to apply.

## 7. EVIDENCE CONVENTION

Used throughout, most heavily in the two research documents:

`[V]` verified at a named source · `[R]` reported by a secondary source · `[C]` my analysis or conclusion · `[U]`/`[UNVERIFIED]` asserted but not checked — **verify before relying on it.**

Requirement tags in the specifications: `[PR]` product requirement, non-negotiable · `[TD]` technical decision, with alternatives documented · `[OPT]` optional implementation choice · `[FUT]` specified but not built in Phase 1.

---

## 8. THE TEST THE BUILD MUST PASS

With **one user and no other humans on the platform**, that user can:

1. Find a real, currently-open opportunity relevant to their country.
2. Get a truthful eligibility verdict with the source sentence it came from.
3. Track it and be reminded before it closes, via Telegram, without an email.
4. Read a structured brief instead of downloading a PDF.
5. Do all of it in under 500 KB of transfer.
6. Encounter **no empty social surface** anywhere.

Everything involving other people is additive on top of a product that already works alone. That is the design's central bet, and it is what the phasing in `IMPLEMENTATION_PLAN.md` protects.
