# AI_SYSTEM.md

**Governing rule:** AI runs **at ingestion, not at query time**. The product must remain fully usable with every AI quota exhausted. If a feature cannot state its deterministic fallback, it does not ship. `[PR]`

---

## 1. WHAT AI DOES AND DOES NOT DO

### Built (exhaustive)
| # | Capability | Trigger | Runs per | Cached |
|---|---|---|---|---|
| 1 | Structured extraction | Ingestion | Document | Permanently |
| 2 | Eligibility rule derivation | Ingestion | Document | Permanently |
| 3 | Brief Decoder | On demand, then never again | Opportunity | Permanently |
| 4 | NL query compiler | Query | Normalised query string | 7 days (KV) |
| 5 | Embeddings | Batch | Record | Permanently |
| 6 | Duplicate candidate scoring | Ingestion | Candidate pair | Permanently |
| 7 | Moderation pre-screen | User submit | Submission | 24 h |

### Deliberately not built `[PR]`
Judging simulation · hackathon copilot · generic idea generation · chat assistant · AI-written marketing copy · AI-generated opportunity descriptions presented as editorial · personality or "compatibility" scoring of people.

**Rationale (from `01_PASS2_CRITIQUE.md`):** each is a commodity LLM output the user can get free, from a better model than our quota affords, in one prompt. Shipping a worse version of a free commodity is negative differentiation — and judging simulation additionally manufactures false authority that users will optimise against.

## 2. HARD GUARDRAILS `[PR]`

1. **No invention.** Every user-visible opportunity fact traces to a stored record derived from a fetched document. AI may structure text; it may never supply a fact absent from the source.
2. **Schema or discard.** Output failing JSON-schema validation is discarded and retried once with a repair prompt, then routed to human review. Partially valid output is never rendered.
3. **Quote or nothing.** Any extracted eligibility rule without a verbatim `source_quote` present in the source text is rejected. Verified by substring match after whitespace normalisation, not by trusting the model. `[PR]`
4. **Confidence gates publication.** Below threshold → review queue, never auto-publish.
5. **No personal data to training-tier providers.** Gemini free tier and Mistral experiment tier use inputs for improvement. Routing enforces this; in practice no user profile text is sent to any LLM.
6. **No model name in application code.** Models are configuration rows. Free catalogues change without notice (Cerebras has dropped models silently; Gemini removed Pro from the free tier).
7. **Every caller handles `NO_AI`.** The provider interface returns a discriminated union, so the compiler enforces it.
8. **AI-derived, user-visible content is labelled** and shows its source quote.

## 3. PROVIDER LAYER

### 3.1 Chain
```
1. Groq          — llama-3.1-8b-instant   fast, ~14,400 rpd, 6k tpm (TPM binds first)
2. Gemini        — 2.5/3 Flash            ~1,500 rpd, 1M context (long docs)  [public content only]
3. Cerebras      — listed model           ~14,400 rpd, volatile catalogue
4. Workers AI    — @cf/meta/llama-*        10,000 neurons/day, at the edge
5. NO_AI         — deterministic fallback
```

Routing by task, not fixed order:
| Task | Preferred | Why |
|---|---|---|
| Extraction (long HTML) | Gemini Flash | Large context handles a full page without chunking |
| Rule derivation | Groq 8B | Short, structured, high volume |
| Brief Decoder | Gemini Flash | Long rules documents |
| Query compiler | Groq | Latency-sensitive |
| Moderation pre-screen | Workers AI | Edge-local, tiny |
| Embeddings | **Local, in GitHub Actions** | Free and unquota'd |

### 3.2 Accounting and circuit breaking
A token-bucket accountant persisted in Cloudflare KV tracks RPM/RPD/TPM per provider. A provider returning 429 or timing out trips a breaker for 15 minutes. All consumption is logged to `ai_usage`. The daily `budget-report` job alerts the operator via Telegram at 70% and 90% of any provider's daily quota.

### 3.3 The embeddings decision `[TD]`
Embeddings are generated by `bge-small-en-v1.5` (384-dim) running **locally inside GitHub Actions** — free, unlimited, no rate limit, no vendor risk. Only *query* embeddings use Workers AI at request time, KV-cached by normalised query.

This single decision removes the largest potential quota consumer from the budget entirely. Without it, embedding 8,000 opportunities plus 5,000 profiles plus re-embedding on edits would exhaust every free API within days.

## 4. CAPABILITY 1 — STRUCTURED EXTRACTION

**Input:** `raw_documents.text_raw` (≤ 40 KB), the source's defaults, and any JSON-LD found.
**Output:** a candidate opportunity conforming to a strict schema.

**Prompt contract (versioned as `extract.v1`):**
- System: *"You convert a web page into a structured record. You may only use information present in the page. If a field is not stated, return null — never infer, never estimate, never use general knowledge. Return JSON only."*
- Include the page text, the current date (for relative-date resolution), and the source's default region/category as **hints only, explicitly overridable by the page**.
- Ask for `field_confidence` per field, 0–1.

**Schema highlights:** `title`, `organisation_name`, `summary` (≤400 chars, **paraphrased in our own words — copying source sentences is a schema violation**), `category_code`, `deadline` `{value, precision, timezone, raw_string}`, `eligibility_scope`, `eligible_countries[]`, `participation_mode`, `team {required,min,max}`, `prize {amount,currency}`, `cost`, `apply_url`, `official_url`, `tags[]`.

**Post-validation, deterministic `[PR]`:**
- Country codes must be valid ISO 3166-1 alpha-2.
- `deadline.raw_string` must appear verbatim in the source text.
- Dates in the past → `precision` downgraded and flagged.
- Currency must be ISO 4217.
- `summary` must not contain any 8-consecutive-word sequence from the source (copyright and paraphrase check). Failure → regenerate once, then queue for human summary.
- Confidence floor: `0.75` overall **and** `0.80` on `deadline` and `eligible_countries` for auto-publish. Below → `in_review`.

**Fallback (`NO_AI`):** JSON-LD and microdata parsing only. If the page exposes `schema.org/Event` or `EducationalOccupationalProgram`, build a partial record and queue it. Otherwise the document waits. **Nothing is published from a failed extraction.** `[PR]`

**Expected accuracy `[C]`:** small models are reliable on title, organisation and URLs; moderate on dates; weakest on eligibility nuance and prize structure. The confidence gates and the human queue exist precisely because of this — do not tune them away to increase throughput.

## 5. CAPABILITY 2 — ELIGIBILITY RULE DERIVATION

The most important AI task in the system, and the most tightly constrained.

**Input:** source text plus the extracted record.
**Output:** an array of rules, each `{ rule_type, params, source_quote, confidence }`.

**Prompt contract (`rules.v1`):**
- System: *"Extract eligibility constraints. For every rule you output you must include the exact sentence from the document that states it, copied character-for-character. If you cannot find such a sentence, do not output the rule. Prefer omitting a rule over guessing one."*
- Provide the enumerated `rule_type` list and parameter shapes.
- Explicitly instruct: *"'Open to Africa' means `country_in` with all 54 African countries, not `global`. 'Open to all countries' means `global`. If residency versus citizenship is unclear, output `residency_required` with confidence below 0.5 and note the ambiguity."*

**Deterministic post-validation `[PR]`:**
1. `source_quote` must be a verbatim substring of the source (whitespace-normalised). **No match → rule discarded.**
2. `country_in` lists are expanded from region words using our own `regions` table, never the model's country list.
3. Contradictory rules (`country_in` and `country_not_in` overlapping) → both flagged, opportunity to review queue.
4. High-stakes rule types (`country_in`, `country_not_in`, `nationality_in`, `age_between`, `student_status_in`) below confidence 0.80 are stored with `confidence` intact but force the aggregate verdict to `unclear` at evaluation time.

**Fallback (`NO_AI`):** no rules are created. Every verdict for that opportunity is `unclear`, displayed honestly as *"We haven't been able to confirm the eligibility rules for this one — check the official page."* This is an acceptable, truthful degraded state. `[PR]`

**Human correction loop:** admins may edit rules, but the editor **requires** a `source_quote` field — the invariant holds for human edits too. A user flag on a verdict creates a review item that shows the rule, the quote and the source side by side.

## 6. CAPABILITY 3 — BRIEF DECODER

Replaces the brief's "AI idea generator", "hackathon copilot" and "judging simulator" with something that cannot hallucinate: **extraction of what the rules already say.**

**Input:** the official rules page or PDF text.
**Output:** `theme`, `deliverables[]`, `judging_criteria[] {name, weight, quote}`, `key_dates[]`, `submission_format`, `prohibitions[]` — **every item carrying a source quote**.

**Value:** replaces downloading a multi-megabyte PDF on a phone over data costing up to $43.75/GB with a ~6 KB structured page. Generated once, cached forever, served to everyone.

**Guardrails:** same verbatim-quote validation as §5. Items without a quote are dropped. If fewer than two items survive, the brief is not published and the page shows the source link instead.

**Fallback:** section hidden entirely; link to the official document shown.

## 7. CAPABILITY 4 — NL QUERY COMPILER

**Input:** the user's natural-language string. **Output:** filter chips only. Never results, never prose. `[PR]`

**Prompt contract (`compile.v1`):** the model receives the *valid filter vocabulary* (category codes, country codes, tag slugs, enum values) and must map the query onto it. Anything unmappable is returned in `unmapped_terms` and handled as keyword text.

**Guardrails:**
- Output validated against the live filter vocabulary; unknown values discarded.
- Cached in KV by normalised query string for 7 days — most queries repeat.
- The user always sees and can edit the chips before or after results render.

**Fallback (`NO_AI`):** a deterministic heuristic matcher — country names and demonyms → ISO codes, category synonyms → category codes, "remote"/"online" → mode, "closing soon"/"this month" → deadline state, remaining words → FTS. This covers a large share of real queries without any model. `[PR]`

## 8. CAPABILITY 5 — EMBEDDINGS

| Object | Text composed from | Refresh |
|---|---|---|
| Opportunity | title + summary + category + tags + organisation + eligibility scope | On publish and on material edit |
| Project | title + pitch + problem + solution + tags | On save |
| Profile | skills + technologies + interests + headline | On save, max once/hour |

Model: `bge-small-en-v1.5`, 384-dim, stored as `halfvec(384)`. Normalised for cosine. HNSW index.

**Never embed:** eligibility profile fields, tracker notes, messages, email addresses. `[PR]`

## 9. CAPABILITY 6 — DUPLICATE CANDIDATE SCORING

Deterministic first, AI last:
1. Canonical URL match → certain duplicate, auto-merge.
2. `pg_trgm` similarity on title ≥ 0.62 **and** same organisation **and** deadline within ±3 days → high-confidence candidate.
3. Embedding cosine ≥ 0.90 **and** deadline within ±7 days → candidate.
4. **Only candidates surviving 2 or 3** go to the model, which answers a single question: *same opportunity, or different? Answer `same`, `different`, or `unsure`, with a one-sentence reason.*
5. `same` with confidence ≥ 0.85 → auto-merge (keeping the highest-verification record as canonical). Anything else → review queue.

**Fallback:** steps 1–3 only; everything ambiguous queues.

## 10. CAPABILITY 7 — MODERATION PRE-SCREEN

Runs on user-submitted free text (project descriptions, team pitches, request messages, reports) and on ingested descriptions.

Returns `{ spam, scam_indicators, harassment, personal_data_leak, off_topic }`, each 0–1, plus flagged spans.

**Deterministic checks run first and are never skipped `[PR]`:** URL allowlist/denylist, Safe Browsing lookup, fee-and-payment keyword patterns (`processing fee`, `registration fee`, `send money`, `western union`, crypto wallet patterns), contact-detail patterns (phone, email) in fields where they are not permitted, and repetition/entropy heuristics.

**Action matrix:**
| Signal | Action |
|---|---|
| Deterministic scam/fee pattern | Block submission; route to review; never auto-publish |
| Safe Browsing hit | Block the link; render as plain text |
| Model score > 0.8 on any axis | Hold for review, author sees "under review" |
| Model score 0.5–0.8 | Publish but queue for review |
| `NO_AI` | Deterministic checks only; everything else publishes and queues at low priority |

The system fails **open for availability and closed for money** — an AI outage never blocks ordinary participation, but never allows a fee-bearing or flagged-link item through. `[PR]`

## 11. COST MODEL

Estimated steady state at Phase-3 scale (≈60 new documents/day):

| Task | Calls/day | Tokens in/out | Provider |
|---|---|---|---|
| Extraction | ~60 | 6,000 / 800 | Gemini Flash |
| Rule derivation | ~60 | 3,000 / 500 | Groq 8B |
| Brief Decoder | ~10 | 8,000 / 1,200 | Gemini Flash |
| Query compiler | ~200 (≈70% cache-hit → ~60 calls) | 400 / 120 | Groq |
| Dedupe adjudication | ~15 | 800 / 80 | Groq |
| Moderation | ~40 | 500 / 60 | Workers AI |
| **Embeddings** | ~500 | — | **local, free** |

Total ≈ **245 LLM calls/day** against a combined free ceiling in the tens of thousands. Headroom is roughly 50×, which is the margin that absorbs a provider disappearing.

**Cost-control techniques in use:** permanent caching of per-document outputs; deterministic pre-filters before every model call; local embeddings; batching; small models for small tasks; user-triggered (not automatic) brief generation; KV caching of query compilation; strict input truncation.

## 12. EVALUATION AND MONITORING `[PR]`

**Golden set:** 60 hand-labelled real opportunities spanning every category, all six Tier-1 countries and every rule type. Checked into the repo as fixtures.

Tracked per prompt version:
| Metric | Target | Action if breached |
|---|---|---|
| Deadline exact-match | ≥ 0.90 | Roll back prompt version |
| Country-eligibility F1 | ≥ 0.92 | Roll back; raise confidence gate |
| Quote-verbatim pass rate | ≥ 0.98 | Investigate immediately — this is the trust invariant |
| Schema-valid rate | ≥ 0.95 | Add repair step |
| False `eligible` rate | **0** | Stop auto-publish until resolved |

A false `eligible` is treated as a **severity-1 defect**, not a quality metric. The system is allowed to be unhelpful; it is not allowed to be wrong about eligibility. `[PR]`

Prompts are versioned files in the repo. Changing one requires the golden set to pass and writes a row to the admin audit log.

## 13. FAILURE MATRIX

| Failure | User-visible effect | System behaviour |
|---|---|---|
| One provider down | None | Chain falls through |
| All providers down | Search still works; no new opportunities publish; briefs hidden | `NO_AI` everywhere; admin alerted |
| Extraction degrades | Fewer new listings | Confidence gate holds; queue grows; alert at 70% below-threshold |
| Rules missing | Verdicts show `unclear` | Honest degraded state |
| Embeddings stale | Slightly worse ranking | FTS carries retrieval |
| Query compiler down | Chips come from heuristics | Notice shown once |
| Moderation model down | Deterministic checks only | Queue priority raised |

**Nothing in this matrix takes the product offline, and nothing in it causes an untrue statement to be shown.** That is the design target for the AI tier.
